## 1. Global Specifications & Data Origin

> [!IMPORTANT]
> **Synthetic Demonstration Data Standard**  
> All responses generated by this demonstration tier originate from the reproducible synthetic Karnataka agricultural dataset.  
> Every response object contains the explicit indicators:
> ```json
> {
>   "is_demo": true,
>   "data_source": "synthetic"
> }
> ```
> Standard units across all endpoints:
> - **Prices**: `INR/quintal` (₹ per 100 kg)
> - **Arrivals**: `quintals` (1 quintal = 100 kg)
> - **Distance**: `km`
> - **Dates**: ISO 8601 strings in `YYYY-MM-DD`

## 3. Error Responses & HTTP Status Codes

All domain errors adhere to a standardized schema:
```json
{
  "error": true,
  "message": "Human-readable explanation of error",
  "details": {}
}
```

| HTTP Status | Condition | Example Response |
| :--- | :--- | :--- |
| **`400 Bad Request`** | Start date later than end date or malformed date format | `{"error": true, "message": "start_date (2026-06-01) cannot be later than end_date (2025-01-01).", "details": {}}` |
| **`404 Not Found`** | Requested crop or mandi does not exist | `{"error": true, "message": "Unknown crop 'dragonfruit'. Supported crops: Tomato, Onion, Potato, Maize, Green Chilli, Ragi.", "details": {"requested_crop": "dragonfruit"}}` |
| **`422 Unprocessable`** | Pydantic query param validation failure (e.g. `limit=-5`) | Standard FastAPI validation payload with param location and error type |
| **`500 Internal Error`** | File system or data loading failure | Standard AgriNexaException error structure |

## 7. Smart Harvest Split Optimizer

### `POST /api/v1/optimizer/harvest-split`

Computes optimal harvest allocation between immediate Day 0 sale and multi-day storage hold, distributing produce across candidate Karnataka APMC mandis using scipy linear programming.

**Request Body** (`application/json`):

```json
{
  "crop_id": "crop_tomato",
  "total_harvest_qty": 100.0,
  "harvest_date": "2026-10-30",
  "origin_mandi_id": "mandi_kolar",
  "preferred_mandi_ids": ["mandi_kolar", "mandi_bengaluru"],
  "storage_capacity_qty": 60.0,
  "storage_type": "ambient",
  "storage_cost_per_qtl_day": 3.5,
  "freight_rate_per_km_qtl": 2.25,
  "handling_charge_per_qtl": 10.0,
  "daily_selling_capacity": 40.0,
  "max_storage_days": 7,
  "risk_preference": "balanced"
}
```

| Field | Type | Required | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `crop_id` | string | ✓ | — | Crop identifier, e.g. `crop_tomato` |
| `total_harvest_qty` | float | ✓ | — | Total harvest volume in quintals (must be > 0) |
| `harvest_date` | string | — | `"2026-10-25"` | Harvest date in YYYY-MM-DD |
| `origin_mandi_id` | string | — | `"mandi_kolar"` | Farm vicinity mandi for distance benchmarking |
| `preferred_mandi_ids` | string[] | — | all mandis | Subset of mandis to consider |
| `storage_capacity_qty` | float | — | `0.0` | Max storage in quintals (0 = no storage) |
| `storage_type` | string | — | `"ambient"` | `"ambient"` or `"cold"` |
| `storage_cost_per_qtl_day` | float | — | 3.5 / 8.0 | Override storage rate (₹/qtl/day) |
| `freight_rate_per_km_qtl` | float | — | `2.25` | Freight cost (₹/km/qtl) |
| `handling_charge_per_qtl` | float | — | per-mandi | Override handling charge (₹/qtl) |
| `daily_selling_capacity` | float | — | unlimited | Max qtl dispatchable per day (must be > 0 if set) |
| `max_storage_days` | int | — | `14` | Max days farmer wants to store (0–30) |
| `risk_preference` | string | — | `"balanced"` | `"conservative"`, `"balanced"`, or `"growth"` |

**Key Constraints Enforced:**
- Total Sales + Total Spoilage + Terminal Unsold = Total Harvest (conservation)
- Shelf-life day T is the final permitted selling day; day T+1 is first prohibited
- Daily sales across all mandis ≤ daily_selling_capacity
- Inventory never exceeds storage capacity
- Storage costs charged only on inventory held (never on sold produce)
- Terminal unsold produce has ₹0 salvage value
- All forecasts are labeled as synthetic/simulated data

## 9. Farmer Authentication, Subscriptions & AI Prediction Protection (Task 7)

### 9.1 Farmer Authentication & Profile Endpoints
- **`POST /api/v1/auth/signup`**
  - **Body**: `{ "full_name": string, "mobile": "10-digits", "email": optional_string, "password": string, "confirm_password": string, "preferred_language": "en" | "kn", "district": string, "preferred_crops": string[] }`
  - **Security**: Passwords salted and hashed with PBKDF2-HMAC-SHA256 (600,000 rounds).
  - **Response `201 Created`**: Returns `{ "access_token": string, "token_type": "bearer", "user": UserResponse }`.
- **`POST /api/v1/auth/login`**
  - **Body**: `{ "identifier": "mobile or email", "password": string, "remember_me": boolean }`
  - **Response `200 OK`**: Returns `{ "access_token": string, "token_type": "bearer", "user": UserResponse }`.
- **`GET /api/v1/auth/me`**
  - **Header**: `Authorization: Bearer <token>`
  - **Response `200 OK`**: Returns current authenticated user profile and active subscription plan.
- **`PUT /api/v1/auth/profile`**
  - **Header**: `Authorization: Bearer <token>`
  - **Body**: `{ "full_name": optional, "email": optional, "preferred_language": optional, "district": optional, "preferred_crops": optional }`
  - **Response `200 OK`**: Returns updated user profile.
- **`POST /api/v1/auth/forgot-password`**
  - **Body**: `{ "identifier": "mobile or email" }`

### 9.3 AI Prediction Protection (35% Loss Benefit) Endpoints
Benefit formula:
$$\text{Compensation} = \text{Verified Eligible Loss} \times 35\%$$
$$\text{Gross Loss} = \max(0, \text{Predicted Price} - \text{Actual Price}) \times \text{Sold Quantity}$$
$$\text{Verified Eligible Loss} = \max(0, \text{Gross Loss} - \text{Excluded Loss})$$

- **`GET /api/v1/protection/predictions`**
  - **Header**: `Authorization: Bearer <token>`
  - **Response `200 OK`**: Returns immutable list of AI predictions available for claim filing.
- **`GET /api/v1/protection/claims`**
  - **Header**: `Authorization: Bearer <token>`
  - **Response `200 OK`**: Returns claims submitted by the logged-in farmer (farmer data isolation).
- **`POST /api/v1/protection/claims`**
  - **Header**: `Authorization: Bearer <token>`
  - **Body**: `{ "prediction_id": string, "crop_id": string, "crop_name": string, "mandi_id": string, "mandi_name": string, "harvest_quantity_qtl": float, "actual_selling_price": float, "date_of_sale": "YYYY-MM-DD", "evidence_description": string, "financial_impact_description": string }`
  - **Response `201 Created`**: Returns created `ClaimResponse` with verified eligible loss and proposed 35% compensation.
- **`GET /api/v1/protection/claims/{claim_id}`**
  - **Header**: `Authorization: Bearer <token>`
  - **Response `200 OK`**: Returns claim details. Enforces isolation (403 Forbidden if accessed by another farmer).
- **`GET /api/v1/protection/claims/{claim_id}/audit`**
  - **Header**: `Authorization: Bearer <token>`
  - **Response `200 OK`**: Returns complete lifecycle audit trail of the claim.
- **`GET /api/v1/admin/protection/claims`**
  - **Header**: `Authorization: Bearer <admin_token>`
  - **Response `200 OK`**: Reviewer console endpoint listing all claims platform-wide (requires reviewer/admin role).
- **`POST /api/v1/admin/protection/claims/{claim_id}/review`**
  - **Header**: `Authorization: Bearer <admin_token>`
  - **Body**: `{ "action": "APPROVE" | "REJECT" | "REQUEST_EVIDENCE" | "PROCESS_COMPENSATION" | "PAY" | "CLOSE", "reviewer_notes": string, "adjusted_excluded_loss": optional_float }`
  - **Response `200 OK`**: Returns updated claim. Prevents farmers from reviewing their own claims (403 Forbidden).
